## Bucket E - Not verifiable from this pass

Say so rather than guess. Each needs a live instance, an external document, or a conversation.

- Exact Cognigy `type`, `extension`, and config keys for `task`, `emailNotification`, `overwriteAnalytics`, `llmPrompt`, `once`. Best source: `manage_flow_nodes get` on a real node or a package export from a Pass-grade build.
- Whether `goTo` `executionMode: "execute"` is the Execute Flow equivalent.
- Whether `mode: "prepend"` works on a freshly created empty flow (no Job node).
- The platform-side 1000-char limit on agent `instructions`, the Code Node 200,000-line limit, and the snapshot cap of 10.
- Whether one Cognigy API key can span the projects the team works in (decides the multi-tenant scope).
- Whether Cognigy exposes any simulation/test-execution API (decides Testing Automation).
- The Cognigy OpenAPI section inventory and which sections the plugin has never evaluated (Handover, Extensions, Playbooks, Locales, Tokens). The roadmap says this review was done; the artifact lives outside this pass.
- **Resolved.** Upstream reworked the Code Node PR on branch `origin/fix/code-node-platform-constraints` (David Scheier, first commit 2026-09-03, two days after `030e9c6`; merged into `main` 2026-09-15). It became `src/tools/codeNodeHints.ts`: 61 lines, four rules, non-blocking ("Hints, never gates"), no `schemas/tools.ts` change, wired into `create_tool`/`update_tool` pre/post-process code the fork never covered.
- **Now evidenced.** Of 8 checks the fork submitted upstream, 2 were adopted and both downgraded to hints; a third survived as a subset; 5 were dropped; the blocking mechanism was rejected outright. The pattern: the maintainer keeps rules stating what the platform cannot do and drops rules encoding how we think code should be written.
- Everything in the Feasibility Assessment and Gap Analysis beyond what the roadmap quotes; those documents should be folded in and this file's Bucket B severities re-checked against them.
